## Findings by persona

### CEO — Strategy & Value

- **PR4 — RISK:** the approved currency extension adds quoting and data migration beyond the five original operations.
  - Evidence: design sections 1, 5 and 10; explicit overview approval of item 1.
  - Action/owner: Codex retains existing base-order compatibility, excludes live FX/payments/tax engines, and uses the revised estimate instead of the pre-conversion estimate.

### CTO — Architecture & Technical Direction

No additional finding after deduplication. Inward dependencies, exact arithmetic,
transaction-scoped repositories, database-time expiry checks and fixed snapshots
are specified. Q2 now has deterministic startup/failure/staleness/recovery rules.
Readiness is explicitly local to a process and does not claim a queue latency SLO.

### CIO — Operations, Security & Compliance

- **PR2 — RISK:** error/telemetry changes can expose secrets or report commits that never happened if field/timing rules are not enforced.
  - Evidence: design section 7 and current generic error/logging paths in `api/rest/server.go`.
  - Action/owner: Codex implements allowlisted fields, server request IDs, safe error classification and post-commit/replayed outcomes; T7 tests secrets and failed transactions.
- **PR3 — RISK:** process-local fixed-window/IP quotas allow boundary bursts and multiply across replicas; reverse-proxy peers also share a quota.
  - Evidence: design section 7 deliberately ignores forwarded headers and uses bounded local maps.
  - Action/owner: Codex implements in-flight bounds and exhaustion tests, documents limitations and preserves these defaults; distributed enforcement is outside the approved implementation.

### CFO — Cost & Resource Economics

- **PR5 — RISK:** manually managed exchange rates have no automatic freshness or market-price guarantee, and expiry can interrupt regional ordering.
  - Evidence: design section 3 requires explicit validity, non-overlapping rates and no fallback; section 8 describes the operator flow.
  - Action/owner: Codex supplies the rate-import/runbook path, demonstrates consecutive validity windows and safe expiry errors, and avoids presenting fixture rates as live values.

### Business Admin — Process & Adoption

No additional finding after deduplication. PR5 includes initialization/rate upkeep.
The existing items-only request remains a base-currency purchase; regional clients
must request and submit a quote. Document this distinction prominently in OpenAPI,
README and smoke examples to prevent accidental assumptions about region defaults.
Explicit initialization protects populated catalogs; mixed historical currencies
require investigation instead of an irreversible automated reinterpretation.

### Data Analytics — Measurement & Data Quality

No additional finding after deduplication. Orders preserve source/target amounts,
rate/version/validity and region mapping, while legacy unknowns remain NULL.
Totals reconcile from rounded unit prices. Worker observations and safe mutation
logs provide evidence without adding a warehouse or durable audit-history table.
