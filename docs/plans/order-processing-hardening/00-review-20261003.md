# Engineering design review

Read with the [overview](01-overview.md), [engineering design](02-engineering-doc.md)
and [local test plan](04-test-plan.md).

| Review perspective | Design decision / boundary |
| --- | --- |
| Product scope | Preserve the five core order operations; regional quotes and auth are supporting extensions. |
| Architecture | Use a layered Go application and one PostgreSQL transaction boundary. |
| Operations and security | Expose worker readiness, bound auth work and keep secrets out of logs. |
| Financial correctness | Persist catalog denomination, use minor units and snapshot accepted conversion terms. |
| Administration | Require explicit adoption for legacy catalog currency and explicit managed-rate imports. |
| Observability | Use structured mutation/worker logs; metrics and durable status history remain future work. |
| Data science | No ML or statistical model is required. |
| Engineering quality | Test rollback, retry conflicts, ownership and concurrent transitions with PostgreSQL. |
| Delivery | Provide reproducible local setup, tests and a live-demo runbook. |

Managed rates can expire, per-process auth limits do not coordinate replicas,
and separate API replicas have independent worker schedules. These are documented
operating constraints. Run tests locally; generated execution records are not
part of the assignment documentation.
